# ADR-0008：学习引擎采用确定性模板与规则评分，LLM 永不作为事实依据

- 状态：已接受（阶段 5）
- 日期：2026-10-24
- 影响：packages/learning-engine、contracts（Exercise/Attempt 增量）、apps/server 学习路由、VS Code 学习区

## 背景

阶段 5 要求围绕真实工程决策构建 Problem→Predict→Explain→Verify→Transfer 学习流程。核心张力：教学内容从哪来？答案如何判？进度如何信？

## 决策

1. **内容生成 = 确定性模板**（v0.1 唯一实现）：题目、选项、提示、解释、反馈全部由该决策的真实 Decision/Claim/CodeAnchor/Evidence 派生。
   - Predict（predict_choice）：选项 = 所选方案 + 真实备选名；**无备选则跳过该题**（单选无意义）。
   - Verify（locate_code）：答案键 = 真实锚点的 filePath+symbolName；**无锚点则跳过——绝不虚构符号**。Level 1 提示直接给出真实位置。
   - Transfer（open_explanation）：rubric 关键词取自备选名/所选方案/主张片段/锚点符号名（分段抽取，≤6 个）。
   - Explain：解释文本逐句引用真实主张与备选；无证据时解释中**不出现**"已被证据支撑"等表述（测试强制）。
   - 数据不足到无法教学（无任何主张）→ 拒绝生成而非编造。
2. **评分 = 确定性规则**：选择题按索引；定位题按锚点精确匹配（接受多种答案格式）；开放题按关键词命中数分 pass/partial/fail 三档，反馈必须点名"真实设计要点"。`Attempt.gradedBy` 记录评分来源（deterministic/self/llm）；**未来接入 LLM 评分时永不作为绝对正确的事实**（只允许作为参考标注，contract 层已预留枚举值）。
3. **答案键不下发**：answerKey 只存服务端，学习会话视图真正剥离该键（键不出现，非置 undefined）；评分在服务端完成。
4. **进度 = Attempt 派生**：练习完成 ⇔ 存在 pass 作答；级别推荐取最近一次作答（fail→Level 1 完整引导，pass/partial→Level 3 独立，无→Level 2 提示式）。不新增"进度"实体——重开插件/重启服务自然恢复。
5. **生成幂等**：已有练习的决策再生成直接返回（不重复出题、不破坏作答）——学习功能可被随意触发而不影响 Agent 开发数据。

## 备选方案

- **LLM 生成题目/解释**：无法保证与真实工程绑定，且引入不可复现性；保留为未来可配置内容源（内容提供者接口位置已留，见 engine 注释），届时必须满足"能引用真实工程信息"并接受完整性审计。
- **LLM 评放开放题**：违背"不把 LLM 评分当事实"——v0.1 直接不实现。
- **新增 Progress 实体**：与 Attempt 冗余，且两处状态可能不一致；派生方案无此问题。

## 后果

- 题目措辞由模板决定，多样性有限——以"与真实工程严格绑定"为优先（PRD 的核心立场）。
- 中文开放题 rubric 是词段子串匹配，偏严格；反馈会列出全部真实要点引导重写（教学上可接受）。
- 学习表（exercises/attempts）与决策表分离，任何学习操作不触碰决策状态与完整性（有测试强制）。
