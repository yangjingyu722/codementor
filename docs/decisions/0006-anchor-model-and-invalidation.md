# ADR-0006：锚定模型——符号优先重定位、显式失效状态与关联来源三角

- 状态：已接受（阶段 3）
- 日期：2026-10-24
- 影响：packages/contracts（CodeAnchor v0.2）、packages/code-mapping、packages/storage（0002 迁移）

## 背景

决策与代码的关联（CodeAnchor）面临三个现实问题：行号会漂移、文件会重命名/删除、自动匹配的关联可能是错的。数据契约必须让"不确定"显式可见，而不是假装精确。

## 决策

### 1. 锚点结构（v0.2）

相对路径 + 符号链（symbolPath，必填）+ 符号类别 + 行范围 + **符号文本 SHA-256**（contentHash，行尾归一 LF）+ 锚定时 HEAD（commitSha）+ **定位状态** + **关联来源** + 锚定时间。

### 2. 状态机：confirmed / ambiguous / missing

重验证（符号优先重定位）规则：

| 情形                                                         | 结果                                            |
| ------------------------------------------------------------ | ----------------------------------------------- |
| 文件中符号唯一定位成功                                       | confirmed，行号/哈希/提交更新                   |
| 文件消失，且 git（-M）检出重命名                             | 跟随到新路径后按上表处理                        |
| 文件或符号不存在                                             | missing（记录与最后已知位置保留，绝不删除）     |
| 同名多候选（如条件编译双定义）、文件语法错误、扩展名无解析器 | ambiguous（不更新位置——绝不展示可能错误的位置） |

关键否决项：**不做全仓库按符号名猜测式回退**。跨文件"搬家"的符号宁可标 missing 也不静默改指别的文件——那正是"静默展示错误位置"的通道。

### 3. 关联来源：declared / inferred

- `declared`：Agent（未来经 MCP 工具）或人显式声明的关联。
- `inferred`：自动匹配被接受后落库的关联，展示层必须标注，不得默认视为正确。
- 自动匹配（`proposeAnchors`）**只产出提案、绝不落库**：符号×决策的归属是语义判断，机器无法从 diff 可靠推断"哪个决策对应哪个符号"，只能给人/Agent 做候选。

### 4. 认知三角（阶段 3 任务 5 的落点）

| 层             | 载体                             | 性质                        |
| -------------- | -------------------------------- | --------------------------- |
| 符号存在       | tree-sitter 解析结果（observed） | 机器事实                    |
| 决策↔符号关联  | CodeAnchor.origin                | 判断（显式标注来源）        |
| 设计理由的解释 | Claim(origin=rationalized)       | 推断（永不升级为 declared） |

### 5. 时间语义

**绝不读取文件修改时间**。版本信息只有 git commit（commitSha）；时间语义只有服务端时钟（anchoredAt/declaredAt）。文件 mtime 与"Agent 何时写代码"无因果关系——同一 checkout 的所有文件 mtime 相同。

## 后果

- CodeAnchor 契约从 v0.1 升 v0.2（symbolPath 转必填、新增 5 字段），存储 0002 迁移加 code_anchors 表（symbol_name 列支撑反向查询索引）。
- UI（阶段 4）必须区分渲染三种状态与两种来源；missing 锚点保留供"设计痕迹"考古。
